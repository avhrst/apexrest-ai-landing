01 / EVERYDAY APEX WORK

Start from a task you already have.

For APEX developers and teams building business applications on Oracle Database: a new app, an existing page, a dashboard or a change that needs checking.

01 / CREATE

Start a new application

Generate APEXlang from a blank app or customer CRM template, then adapt it to your requirements.

02 / ADOPT

Work on the app you have

Export into a new project while preserving Oracle IDs and application metadata. Keep the source in version control.

03 / EDIT

Change pages and components

Update forms, reports and shared components with changes scoped to your request.

04 / DATA

Build useful dashboards

Use real database queries, native APEX regions and filters that submit values and refresh the relevant content.

Plan and import a change

03 / WHAT'S NEW IN 2.5.0

See the page
before you import it.

Since 1.3.0, APEXREST has gained a database-free local preview, partial imports on APEX 26.2 and a much larger offline component library. Eleven tools and six skills, in Codex and Claude Code.

01 / PREVIEW

Run APEXlang without a database

apexrest_preview serves your pages from Node.js and SQLite with the genuine Universal Theme 26.2 templates and JavaScript. An .apx edit appears on the next reload, before anything is compiled or imported.

02 / COVERAGE

Most APEX UI, locally

Interactive reports and editable grids, forms and modal dialogs, faceted search, cards, template components, charts, calendars, maps and native page items. Whatever the preview does not simulate is listed in its diagnostics.

03 / LOGIC

Submits that behave like APEX

A PL/SQL subset interpreter runs processes, validations and computations. Each submit is one transaction that rolls back on error. A developer toolbar shows session state, the debug log and “view as” roles.

04 / APEX 26.2

Import only what changed

Update a page and its shared components without re-importing the whole application. APEXREST compares the baseline, your edits and a fresh export, keeps remote-only changes and blocks conflicts before writing. APEX 26.1 keeps full imports.

05 / LIBRARY

Read before writing

The library grew to 269 compiler-checked recipes, including 93 adapted from official Oracle sources, plus 1,350 public Oracle reference pages. Each recipe carries a data shape, adaptation rules and compiler evidence.

06 / SELECTION

Optional component ranking

With your own OpenAI key, the Decisions API can rank compatible catalog components before generation. It is off unless you configure it; search and read stay fully local, and your host model still writes the APEXlang.

A DESIGN AID, NOT ORACLE EVIDENCE

The preview never replaces compiler validation, an authorized import or browser checks on DEV, QA or TEST. Local repository checks pass; native Codex and Claude Code runs and connected Oracle checks are partial, and the latest repository review lists open defects.

04 / THE WORKFLOW

From a request
to a checked change.

EXAMPLE / EXISTING APP

Add an order status report. Preserve the existing pages and authentication. Import into the named test app and verify the filter.

  1. 01
    SCOPE

    Identify the application.

    Describe the change and name the project and environment. Your agent checks the available app and database context.

  2. 02
    BUILD

    Edit readable source.

    Create or adopt the application, then make bounded changes in APEXlang. Keep schema and data migrations versioned alongside the app.

  3. 03
    CHECK

    Validate before import.

    Preview the pages locally, then run the Oracle compiler. The deployment plan records the source, toolchain and target.

  4. 04
    AUTHORIZE

    Keep the target explicit.

    Your request to update an identified DEV, QA or TEST app authorizes that scoped import. The app is backed up first; on APEX 26.2 only the changed pages are imported.

  5. 05
    VERIFY

    Check the running result.

    When you ask, your agent opens the imported pages in the host’s in-app browser. It reports what it checked, what failed and what it did not verify.

PRODUCTION STAYS YOURS

APEXREST imports only into DEV, QA and TEST targets; production targets always block deployment and restore. Release to production remains your decision. AI output still needs review and testing; compiler validation alone does not prove runtime correctness.

INSTALL THE PLUGINAPACHE-2.0

A short path to your first task.

# Codex
codex plugin marketplace add apexrest-dev/apexrest
codex plugin add apexrest-apex@apexrest

# Claude Code
claude plugin marketplace add apexrest-dev/apexrest
claude plugin install apexrest@apexrest

Both commands read the plugin bundle from the repository, so no build step is needed. Installing the plugin does not configure a connection or deploy an application.

YOUR FIRST REQUEST

Use APEXREST to check my setup. Report the compiler, connection and target checks that still need attention.

For connected Oracle work

  • Java 21 and SQLcl: 26.1.2 for APEX 26.1, 26.3 for APEX 26.2
  • An existing Oracle APEX 26.1 or 26.2 development or test application
  • A saved SQLcl connection or private ORDS credentials

The local preview needs neither Java nor SQLcl. Keep passwords in the local connection settings, outside chat prompts.

Prefer the command-line tool? Install from npm
npm install -g apexrest
apexrest --version
apexrest --help

This installs npm latest, apexrest@2.1.0 at the time of writing. Registry packages lag the repository: the local preview and the current surface are in the 2.5.0 plugin source, so install the plugin for them.

Using Codex Cloud?

A separate guide covers command-line tools with ORDS over HTTPS. Native Cloud plugin discovery and MCP support are not established; the full Cloud workflow still needs end-to-end verification.
