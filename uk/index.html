01 / ПОВСЯКДЕННІ ЗАДАЧІ APEX

Почніть із задачі, яка вже є.

Для APEX-розробників і команд, що створюють бізнес-застосунки на Oracle Database: новий застосунок, наявна сторінка, дашборд чи зміна, яку потрібно перевірити.

01 / СТВОРЕННЯ

Новий застосунок

Згенеруйте APEXlang із порожнього застосунку або шаблону клієнтської CRM та адаптуйте під свої вимоги.

02 / НАЯВНИЙ ЗАСТОСУНОК

Робота з тим, що вже є

Експортуйте в новий проєкт зі збереженням Oracle ID та метаданих застосунку. Зберігайте код у системі контролю версій.

03 / ЗМІНИ

Сторінки й компоненти

Оновлюйте форми, звіти та спільні компоненти в межах вашого запиту.

04 / ДАНІ

Корисні дашборди

Використовуйте реальні запити до БД, нативні регіони APEX і фільтри, які передають значення та оновлюють потрібний вміст.

05 / ДОСТАВКА

План та імпорт змін

Перевірте визначене середовище, прив’яжіть план до перевіреного коду та створіть резервну копію наявного застосунку перед імпортом.

06 / ПЕРЕВІРКА

Тести й діагностика

Запускайте налаштовані SQL-, API- або браузерні перевірки. Досліджуйте діагностику та виправляйте помилки за наявними доказами.

02 / ЧОМУ APEXREST

Знання APEX.
Інструменти для перевірки.

APEXREST надає Codex і Claude Code спеціалізовані навички та інструменти для Oracle APEX. Опис застосунку зберігається у зрозумілих .apx-файлах; Oracle SQLcl перевіряє його перед погодженим імпортом.

Запит, зміни коду та перевірка залишаються в одній розмові.

Як працює Oracle APEX ↗
  1. 01

    Каталоги компонентів і патернів

    Офлайн-каталоги охоплюють 109 сімейств компонентів і 58 повторюваних UX-патернів із перевіреними компілятором рецептами APEXlang. Агент отримує лише те, що потрібно для зміни.

  2. 02

    Потрібний контекст, менше повторів

    Стислі зведення проєкту, пакетне читання метаданих та обмежене очікування задач допомагають уникати повторного збору даних і завеликих відповідей інструментів.

  3. 03

    Ваша база, ваше підключення

    Використовуйте збережене пряме підключення SQLcl або ORDS через HTTPS, коли прямий доступ до бази недоступний.

  4. 04

    Повноцінна платформа застосунків

    Oracle APEX надає форми, звіти, автентифікацію та робочі процеси на Oracle Database — основу для промислової експлуатації вашого застосунку.

03 / ЯК ЦЕ ПРАЦЮЄ

Від запиту
до перевіреної зміни.

ПРИКЛАД / НАЯВНИЙ ЗАСТОСУНОК

Додайте звіт про статуси замовлень. Збережіть наявні сторінки й автентифікацію. Імпортуйте у визначений тестовий застосунок і перевірте фільтр.

  1. 01
    МЕЖІ

    Визначте застосунок.

    Опишіть зміну та вкажіть проєкт і середовище. Агент перевірить доступний контекст застосунку й бази даних.

  2. 02
    РОЗРОБКА

    Змініть зрозумілий код.

    Створіть або експортуйте застосунок, а потім внесіть обмежені зміни в APEXlang. Зберігайте міграції схеми й даних під контролем версій разом із застосунком.

  3. 03
    ПЕРЕВІРКА

    Валідуйте до імпорту.

    Виконайте потрібні перевірки коду та компілятора. План розгортання фіксує код, інструментарій і цільове середовище.

  4. 04
    ДОЗВІЛ

    Погодьте конкретну ціль.

    Ваш запит на оновлення визначеного dev- або test-застосунку може дозволяти імпорт у цих межах. Спершу створюється резервна копія наявного застосунку.

  5. 05
    РЕЗУЛЬТАТ

    Перевірте роботу застосунку.

    Після імпорту виконайте налаштовані тести та потрібні браузерні перевірки. Звіт про помилки й невиконані перевірки допоможе оцінити результат.

ОКРЕМЕ ПОГОДЖЕННЯ PRODUCTION

Production потребує зовнішнього підписаного дозволу на захищеному runner. Результат ШІ потребує рев’ю та тестів; перевірка компілятором сама по собі не доводить коректність роботи застосунку.

05 / ПОЧАТОК РОБОТИ

NPM LATEST · 1.2.0

Oracle APEX
у вашому агенті.

Додайте marketplace. Встановіть плагін. Почніть із перевірки налаштувань.

Той самий пакет плагіна встановлюється з репозиторію в Codex (desktop і CLI) та Claude Code. Потрібен Node 24 LTS.

  1. 01

    Оберіть хост

    Виконайте дві команди для Codex або для Claude Code. Обидві реєструють той самий плагін APEXREST.

  2. 02

    Нехай плагін підготує інструменти

    На ваш запит він покаже та встановить відсутні Java і SQLcl. Спершу ви ознайомитеся з умовами Oracle; база даних не створюється, застосунок не розгортається.

  3. 03

    Почніть нову сесію

    Відкрийте нову задачу в Codex або сесію Claude Code та попросіть APEXREST перевірити налаштування до першої зміни застосунку.

Повна інструкція встановлення ↗Відкритий код на GitHub ↗
ВСТАНОВЛЕННЯ ПЛАГІНАAPACHE-2.0

До першої задачі — кілька кроків.

# Codex
codex plugin marketplace add apexrest-dev/apexrest
codex plugin add apexrest-apex@apexrest

# Claude Code
claude plugin marketplace add apexrest-dev/apexrest
claude plugin install apexrest@apexrest

Обидві команди беруть пакет плагіна з репозиторію, тож збірка не потрібна. Встановлення плагіна не налаштовує підключення і не розгортає застосунок.

ВАШ ПЕРШИЙ ЗАПИТ

Використай APEXREST для перевірки моїх налаштувань. Повідом, які перевірки компілятора, підключення та цільового середовища ще потребують уваги.

Для роботи з Oracle

  • Java 21 та перевірений SQLcl 26.1.2
  • Наявне середовище Oracle APEX 26.1+
  • Збережене підключення SQLcl або приватні дані ORDS

Зберігайте паролі в локальних налаштуваннях підключення, поза запитами в чаті.

Потрібен лише CLI? Встановлення з npm
npm install -g apexrest
apexrest --version
apexrest --help

npm latest — 1.2.0, beta — 1.3.0-beta.1. Обидва пакети досі містять попередній набір інструментів лише для Codex; підтримка Claude Code є в репозиторії.

Працюєте в Codex Cloud?

Окрема інструкція описує CLI та ORDS через HTTPS. Підтримку нативного Cloud-плагіна, MCP і панелі не підтверджено; повний Cloud-процес ще потребує наскрізної перевірки.

Налаштування Cloud ↗

Реліз із відкритими обмеженнями.

Підтримку Claude Code перевірено локально: обидва маніфести плагіна валідні, локальне встановлення працює. Наскрізна сесія Claude Code і встановлення з опублікованого marketplace ще попереду, як і підключені імпорти, відновлення та ширші перевірки платформ. Версія 1.2.0 — актуальний реліз npm latest.
